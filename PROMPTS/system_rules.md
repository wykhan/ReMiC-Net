# system_rules

## Codex Working Rules

- One task should focus on one coherent class of change
- Protocol changes must never be made silently; they require an explicit recorded task
- All experiments must be driven by scripts rather than ad hoc manual steps
- All outputs must be written to fixed repository locations
- Geometry parameters must not be changed without traceable documentation
- Work must not bypass the governing documents in `CONTEXT/`
- If an item is uncertain, record it as TODO or pending instead of inventing a decision
- Bootstrap tasks must not trigger formal simulation, training, or benchmark runs unless the task explicitly authorizes that scope
